# LMRB 1.21.1 移植計画

## 概要

LMRB を Minecraft 1.20.1 (8.11.1) から 1.21.1 (9.0.0) へ移植する。
既存の `origin/1.21` (10.0.0-alpha2) は GameTest 大規模削除・SalaryBox 削除等の設計判断が記録なしに混入しているため破棄し、1.20.1 ブランチをベースに再出発する。

## 確定方針

| 項目 | 決定 |
|------|------|
| ターゲット MC | 1.21.1 ピン留め (Stonecutter 不採用) |
| プラットフォーム | fabric + neoforge (forge は切る) |
| ベースブランチ | `1.20.1` |
| 移植先ブランチ | `1.21.1` |
| バージョン | `9.0.0` |
| 旧 `origin/1.21` | 破棄 (参考程度に diff を眺める用途のみ) |
| 1.20.1 ブランチ | 完全並行開発を継続。1.21.1 への反映は cherry-pick 運用 |
| 作業順序 | LMML 1.21.1 完成 → LMRB 1.21.1 → LMRBCompat 1.21.1 (直列) |
| GameTest | 1.20.1 で整備したテスト群を全て 1.21.1 に移植 |
| API 整理 | 通常移植のみ。TODO の「外部 Mod 連携 API」「ModelCaps 未実装埋め」等は別タスク |
| DataComponents 設計 | 機械的にできる範囲は実施、重い設計判断はユーザーにエスカレ |
| Network パケット | Architectury NetworkManager で抽象化 |

## 作業フェーズ

### フェーズ 0: LMML 1.21.1 化 (前提)

LMRB 着手前に LMML を 1.21.1 で stable にする。LMML 側も `local/1.21` (10.0.0-alpha2) を破棄して 1.20 ベースで再出発。LMML 9.0.0 を目標。

### フェーズ 1: ビルド環境セットアップ

- `1.20.1` から `1.21.1` ブランチを切る
- `gradle.properties` / `settings.gradle` / Architectury Loom plugin 更新
- `forge/` → `neoforge/` リネーム + プラットフォーム実装書き換え
- Java 17 → Java 21 切り替え
- ビルド通過まで持っていく (コンパイルエラーは次フェーズで順次解消)

### フェーズ 2: バニラ API 追従 (大物)

優先度順:

1. **Identifier**: `new Identifier(...)` → `Identifier.of(...)` 一斉置換
2. **ItemStack DataComponents 化** (1.20.5 breaking, **最大の工数**)
   - メイドさん永続データ (契約・スキル・モード等) の NBT を `CUSTOM_DATA` ベースに移行
   - 専用 `DataComponentType` 設計は設計判断が必要なら都度エスカレ
3. **CustomPayload ネットワーク**: 既存 `FabricPacket`/`PacketByteBuf` 直書きを `CustomPayload + PacketCodec` に書き換え。Architectury `NetworkManager` で抽象化
4. **AttributeModifier**: UUID → `Identifier` 化、Operation enum 改名
5. **Entity / Mob API**: `getMobType` 削除 → `EntityTypeTags`、`finalizeSpawn` シグネチャ、`EntityAttachments`
6. **Renderer**: `VertexConsumer.addVertex()`, `BufferBuilder` → `MeshData`、ARGB int tint
7. **Text / Component**: `Serializer` が `RegistryWrapper.WrapperLookup` 必須
8. **NBT 永続化**: `Entity#writeCustomDataToNbt` 等が `HolderLookup.Provider` 引数

### フェーズ 3: Mixin 再検証

- `@At(target=...)` 生 descriptor 全件レビュー
- `ItemStack#getTag` 消滅, `Mob#finalizeSpawn` 引数変化, `GoalSelector` メソッド削除の影響箇所
- Mixin Accessor (`_LM` サフィックス) は対象メソッドが残っているか個別確認

### フェーズ 4: データパック JSON 整備

- ディレクトリ単数形化:
  - `tags/items/` → `tags/item/`
  - `loot_tables/` → `loot_table/`
  - `recipes/` → `recipe/`
  - `gametest/structures/` → `gametest/structure/`
  - `advancements/` → `advancement/`
- モード用タグ (`{mode_name}_mode.json`) 全件移動
- Loot table / Recipe JSON 形式の breaking change (1.20.5) 追従

### フェーズ 5: Enchantment データ駆動化対応

LMRB が直接 enchant 参照している箇所 (主に剣・道具モード) を `Holder<Enchantment>` + `EnchantmentTags` に置換。

### フェーズ 6: GameTest 移植

- ストラクチャーディレクトリ単数形化
- `LMRBCommonTests` のテストメソッドを 1.21.1 API に追従
- Fabric / NeoForge 両方で `runGameTestServer` が通る状態に
- Forge 用 `LMRBForgeGameTests` は NeoForge 版 (`LMRBNeoForgeGameTests`) に書き換え

### フェーズ 7: Cloth Config / AutoConfig 動作確認

API は概ね不変だが、内部の Identifier 構築や Text JSON 化で壊れる可能性あり。
コンフィグ画面を開いて全項目動作確認。

### フェーズ 8: 統合テスト

- ビルド通過 (fabric, neoforge)
- spotlessApply / checkstyle / spotbugs
- `:common:test`
- `:fabric:runGameTestServer` / `:neoforge:runGameTestServer`
- 手動動作確認: メイドさんスポーン, 契約, モード切替, IFF, レンダリング, 設定画面

### フェーズ 9: LMRBCompat 1.21.1 化 (本タスク外、後続)

LMRB 9.0.0 が安定したら LMRBCompat を追従。

## 検証方法

各フェーズで:

- `./gradlew :fabric:build` / `./gradlew :neoforge:build`
- `./gradlew spotlessApply spotlessCheck checkstyleMain spotbugsMain`
- `./gradlew :common:test`
- `./gradlew :fabric:runGameTestServer`

完了基準:

- 全プラットフォームでビルド通過
- GameTest 全件パス
- 手動: 新規ワールドでメイドさんスポーン → 契約 → モード切替 → 戦闘 → 設定画面 が動く

## エスカレが必要な可能性のある設計判断

着手後に都度ユーザー判断を仰ぐもの:

- **DataComponentType の粒度**: 1 個の big component に詰めるか、概念ごとに分割するか
- **AttributeModifier 旧 UUID 定数の置換規則**: 既存 UUID をどう Identifier 化するか (NBT 互換のための変換ロジック要否)
- **forge → neoforge への mods.toml 切り替えで失われる Forge 固有機能の有無**
- **GameTest ストラクチャー NBT の形式変更影響**
